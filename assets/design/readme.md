# Design system

One system, five profiles. The system holds tokens, components and behaviors; every product in `products.json` loads them, and its character is a short profile. Each product lays out and presents its own pages, fit for their purpose, from the tokens.

## Use

    <link rel="stylesheet" href="/static/design/styles.css">
    <button class="btn btn--primary">New Project</button>
    <svg class="icon"><use href="/static/design/icons.svg#add"/></svg>

In this repo `styles.css` imports the token files, `components.css` and the product's `profile.css`; the copy a product receives holds all of them in that order in one file, so a page makes one request for its design, not ten. website serves the copy at `/assets/design/`.

## Principles

1. Every text pair passes WCAG AA in light and dark: 4.5:1 body, 3:1 for 18.66px bold or 24px and up.
2. Focus rings and any edge that alone marks a control pass 3:1. Focus is an outline, so it survives forced colors.
3. One focus recipe: outline 3px `--color-focus`, offset 2px, inset 3px inside lists. A text field inset in a list row shows its caret and no ring.
4. Closed sets. A value that is not a token does not exist, except colors carried by diagram data.
5. One name, one meaning in every product.
6. Every color token has a light and a dark value.
7. Sizes and spaces are multiples of 4; layout steps multiples of 8.
8. One size on every device. Text is 17px; secondary text and small controls 15; footnotes 13. Controls draw at 44px; on touch every smaller one gets a 44px hit area. Display type, `--text-40` and up, may draw a smaller token below 900 than from 900 up, in one step, written either way (`max-width:899px` down or `min-width:900px` up): Principle 14's best steps its headlines down on phones (Apple 80 to 48, 56 to 32), and a 72px headline does not fit one.
9. Motion is a closed set, each part off under reduced motion: 120ms ease for state, 200ms for movement. A chart that draws itself in on arrival takes `--duration-reveal` (800ms), once. Parts arriving in a cascade are `--delay-cascade` (120ms) apart; scroll-driven motion follows the scroll position, never a clock, exists only where the browser supports it, and the page is complete without it. Loading indicators wait `--delay-loading` (400ms) before they show, so fast loads never flash a spinner. Every entrance has a matching exit: sheets, menus, toasts and rows leave as they came. New rows fade up `--delay-stagger` (30ms) apart.
10. The user's settings win: rem tokens follow the browser font size, forced colors keep every control visible, reduced motion stops all movement. Nothing sets the root font size.
11. Every component lives here. A product opts in; a difference between products is a recorded profile choice. A product's own CSS styles only its own classes: it never names a design class, and a product class on a design element sets layout only (margin, flex, grid, width).
12. Every rule a product's files can show is checked by script, on every product push as well as on sync: contrast, stray literals, theme colors, bare hovers, copy, closed parts and modifiers of design classes, component structure and order, page structure, product styles, profile choices, one primary button per view and small buttons. What needs a browser is held by `scripts/layout.cjs` on the design's own pages where a test can; the rest, and what needs judgement, is reviewed. The guard refuses a raw value a token covers, never a product's own layout or classes. Each finding names its file, line and rule.
13. Hover styles sit in `@media (hover:hover)`, so a tap never leaves one on.
14. The best to beat (owner, 24 November 2026): for now Apple, in craft and magical feel; colors Apple like at the very least. A product's approved standard wins where it sets another aim.

## Tokens

| File | Holds |
| --- | --- |
| `tokens/base.css` | Raw palette (`--base-*`). Never used by products |
| `tokens/color.css` | Every color role, light and dark, plus diagram and mark colors |
| `tokens/type.css` | `--font-*`, `--text-{px}`, `--tracking-*`, `--leading-*`, `--weight-*`, `--reading-words-per-minute` (reading time on documents) |
| `tokens/space.css` | `--space-{px}`: 4 8 12 16 24 32 48 64 96 128 |
| `tokens/shape.css` | `--radius-{px}`, `--size-*`, `--width-*`, `--ratio-{wide,portrait,square,thumbnail}` (aspect ratios) |
| `tokens/depth.css` | `--shadow-raised`, `--shadow-float`, `--shadow-deep` (the deepest shadow), `--frost`, `--opacity-*` (including `--opacity-ring-track` and `--opacity-ring-glow`), `--z-*` |
| `tokens/motion.css` | `--duration-state`, `--duration-move`, `--duration-spin`, `--duration-reveal` (a chart drawing in; 0 under reduced motion), `--delay-loading`, `--delay-guard` (how long a just-shown choice ignores taps, so a double tap can't answer twice; kept under reduced motion), `--duration-notice` (how long a toast or copied state stays, in ms; kept under reduced motion), `--delay-stagger` (between rows fading in; 0 under reduced motion), `--ease-*`, `--press-scale`, `--delay-cascade` (between the parts of a cascade arriving; 0 under reduced motion), `--scale-enter` (a start scale; 1 under reduced motion), `--scale-depth` (an overscan scale, 1 plus twice `--drift-travel`) and `--drift-travel` (a travel offset), `--scale-recede` (an end scale), `--scale-glyph`, `--scale-remove`, `--scale-menu` and `--scale-fold` (where a glyph, a remove button, a menu and a folding title start or end) |

Names: numbers by their px value at the default font size, roles by their job, state last (`--color-primary-hover`). `--text-*` is a size only; every color starts with `--color-`.

Colors: `--color-primary`, `-primary-hover`, `-on-primary`, `-accent`, `-accent-hover` (Apple's link blue: #0066cc, #2997ff in dark, darker and lighter again under Increase Contrast; blue is for links only, the owner's word of 24 November 2026, so pages do not look like Apple's), `-text`, `-text-secondary`, `-background`, `-background-grouped`, `-surface`, `-surface-raised`, `-surface-sunken`, `-surface-canvas`, `-fill-subtle`, `-fill`, `-fill-strong`, `-selected`, `-hairline`, `-border-strong`, `-focus`, `-bar`, `-bar-grouped` (sidebar), `-scrim`, `-on-scrim`, `-backdrop`, `-{error,warn,success}`, `-{error,warn,success}-text`, `-on-error`, `-avatar-start`, `-avatar-end`, `-canvas-dot`, `-mark-{blue,green,yellow,pink,olive}` (olive passes 4.5:1 as text on every surface), `-ring-{1,2,3}-{start,end}` (the three rings of a ring chart, each sweeping from its start to its end; they pass 3:1 as large text on plain surfaces).

Hues are Apple's system colors, light and dark. Status hues are for fills and glyphs; text uses the `-text` tokens, Apple's accessible shades, on plain surfaces only. `-on-error` is the text on a red fill. Under Increase Contrast (`prefers-contrast:more`) every hue switches to Apple's accessible value.

Diagram colors: `--color-diagram-{hue}` with `--color-diagram-{hue}-text`, chosen by contrast, for blue, indigo, purple, violet, graphite, pink, red, orange, yellow, green, mint, teal, brown, gray and neutral. Fills follow Apple's light and dark values; neutral turns #3a3a3c. BCM depth: `--color-diagram-depth-1..5` and `--color-diagram-band`. Edges use `--color-text`, edge labels `--color-text-secondary`, boundaries `--color-border-strong`, selection `--color-primary`.

## Components

Classes follow BEM: `.block`, `.block__part`, `.block--variant`, `.is-state`. Every element is border-box. `[hidden]` always hides. Bare `code` takes the mono face; `mark` is semibold text with no fill. Every link inherits its text color, so the browser's link blue never shows. A link without a class gets a hairline underline that turns solid on hover; a classed link sets its own color. `a.link` is a link in the accent color, plain until it is hovered, as Apple's "Learn more" links are; a trailing `svg.icon.icon--sm` chevron-right may follow its words.

- **Button** `.btn` secondary, `--primary` (one per view: the view's create or add action; a dialog is its own view, and the branches of a template `if` count once), `--plain`, `--destructive`, `--destructive-filled`, `--icon` (`aria-label`; no tooltips: a control that needs one is redesigned), sizes `--sm` 28 and default 44; `--sm` never sits in a form, a list row or a cell, where controls draw at 44. `.btn__caret` for menu buttons. `aria-busy="true"` blocks presses and, after `--delay-loading`, swaps the label for a spinner at the same width. `.btn__swap` is the icon a button shows instead of its first while `[aria-pressed="true"]` or `.is-copied`, as in Show and Copy; the copied check springs in.
- **Text field** `.field` > `.field__label` + `.input` (filled), `.input--inset` (in list rows), `.input--prominent` (single field pages), `.input--code` (mono; a textarea keeps its lines and scrolls sideways) + `.field__error`. `.field--inline` puts the label beside it. Invalid: `aria-invalid="true"`. Fields and selects draw at 17, above the 16 under which phones zoom in on focus. An email field sets `autocorrect="on"`: iOS applies the person's text replacements only where autocorrect is on, and it leaves addresses as typed. `.field__note` for a line of help under a field. `fieldset.repeat` holds one of several repeated field sets: an added one is `.is-new` and grows open, a removed one is `.is-leaving` and collapses for `--duration-move`.
- **Search** `.search` > `svg.icon.search__icon` + `input.input`, then an optional `.search__count` on the trailing edge ("3 of 12 people"). A search at the top of a page sits under `.page > .search`. `label.date-filter` > text + `input[type="date"]` is a filled date control.
- **Select** `.select` > `select.select__input` + `svg.icon.icon--sm.select__caret`. `.select--inset` in list rows.
- **Checkbox** `input.checkbox` + `span.checkbox__mark`. **Radio** `input.radio` + `span.radio__mark`.
- **Segmented** `.segmented` (`--sm`) > `.segmented__opt[aria-selected="true"]` or `[aria-current="page"]`. `--scroll` keeps each option's width and scrolls the row; `--fill` fills the row on phones. An option can hold a radio: it shows selected while checked. A segmented `[role="tablist"]` or radio group slides its selected capsule to the new option; a `[role="tabpanel"]` rises in. In a form or dialog it fills the width.
- **Switch** `input.switch[type="checkbox"][switch]` for every on and off setting: Safari draws the system switch and plays its tick; other browsers draw the same shape.
- **Key cap** `kbd.kbd`, one per key, in the ? shortcuts list. Controls never show their shortcut, as in Apple's apps.
- **Badge** `.badge` (`--md`): a tag is a quiet capsule (`.badge`, `--tint` for emphasis) that wraps to more lines inside its container, never wider than it; a status is a dot before plain text (`--neutral`, `--success`, `--warn`, `--error`); a count of things waiting is `--count`, solid red with the number, in the sidebar and tab bar. `.status-dot` (`--alert`, `--unread`, `--off`) is a dot beside a row or nav item.
- **Chip** `.chip` (a `span` for static legend entries; `button`/`a`/`label` react to hover) (`.is-selected`, `[aria-pressed="true"]`, `[aria-current="page"]`) with `.chip__swatch` (`--neutral`) and `.chip__caret`. `--avoid` outlines a chip in `--color-error`, marking an avoid list apart from a favor list; its label or `aria-label` says "avoid", since colour alone is not enough. `[aria-expanded="true"]` (or `.is-open`) shows a chip while its popover is open: a stronger fill and its caret turned. Covers filters, legend chips and nav pills. A chip can hold a radio or checkbox and shows selected while checked. `.chips` is a scrolling row of chips, `.summary` a scrolling row of counts (`b` for the number), `.filters` a wrapping row of filter chips.
- **Nav bar** `.navbar` (`--fold`) > `__left`, `__center` (optional), `__right`, `__title`. With `--fold` the title shows as `.page-title` goes under the bar, wherever it sits on the page, or after a fixed scroll on a page without one. `a.backlink` or `button.backlink` > chevron-left + `.backlink__label`; a button for going back within the page, as from a detail to its list on phones. As `__left`, a back link keeps the chevron's 44 target and shows its whole label or hides it, never cut, the label still its name. Where the whole label fits in half of what the right group leaves, `behaviors.js` gives it its room before the title (`.is-whole`), and the title is cut with an ellipsis; elsewhere, and without the script, the title goes first.
- **Sidebar** `.sidebar` (`--collapsed`) > `.sidebar__togglerow` > `.sidebar__toggle`, `.sidebar__scroll`, `.sidebar-label`, `.sidebar-item` (`.is-selected`) > `__icon`, `__label`, `__count`. `.sidebar__head` holds the search and a new button. A group, or a list on its own, hides when a filter hides every row in it. `aria-busy="true"` on a `.cell` that submits shows a spinner in place of its chevron or trailing part and ignores presses. `.list--add` is a one-row card holding an add action under the list it adds to; `.list--values` gives the value the room, for rows whose value matters more than the label. `.cell__meta--warn` and `--error` lead with a status dot; `.cell__value--strong` draws the value in text color; `.cell--credential` shows a secret in mono. Edit mode: `[data-edit-list]` shows its `.cell__actions` only while `[data-editing]`, which also slides in each `.cell__remove` (a red circle with a white minus) and fades chevrons. A new row is `.list__row.is-new` with `--row-index` set for its stagger; a row on its way out is `.is-leaving` for `--duration-move`. A picker joins `ul.list[data-picked]` and the `.list` that starts the next `[data-results]` into one card; `.picker > .search` sits above them; `.selection` > Select All + `.selection__count` heads a multi-select list. `.timeline` aligns rows to the top with `.timeline__text`, `__meta` and `__time`. `p.hint` is a centered footnote under a list or search.
- **Card** `.card` (`--bordered`) > `.card__body`; `a.thumbnail` > `__preview` + `__body` > `__title` + `__meta`; with actions, `div.thumbnail` > `a.thumbnail__link` (preview + body) + `button.btn.btn--icon.btn--sm.thumbnail__more` (`more` glyph, opens the item's menu, same items as right-click).

It fades in and rises, then falls and fades out; a tap outside closes every dialog but an alert. Sizes: every pill-shaped control is 28 (`--sm`: 12 padding, 15 type) or 44 (default: 16, 17). Buttons of every variant, chips (28), segmented controls, nav items and the skip link share this geometry; a variant changes only its paint, so a hover, selected or primary fill always draws the same capsule. Badges are 20 on purpose: labels, never pressable. A tag that wraps grows by its lines and keeps the corner of the 20 badge.

States: hover one fill step up, press `scale(var(--press-scale))` with the strong fill, selected `--color-selected` with primary text (a selected dark pill darkens on hover, never fades to grey), disabled 0.4, busy 0.6 with a spinner (a submitting `.cell` shows it too, after `--delay-loading`, in place of its chevron or trailing part, ignoring presses at the row's height), invalid a 2px `--color-error` ring and a `.field__error` message; the edge is only red, so a bordered field's border and every invalid field's focus ring take the error color too. A field fails on submit or on leaving it after a change, never on first load. A wrong code shakes once: `.is-shaking`, removed on `animationend`.

## Behaviors

`behaviors.js` holds every behavior two products share. Load it, before `document.js`, on every page that has a control, dialog, menu, form, tab, popover or data attribute; a page of content and links is complete without it and loads none. It owns focus, announcements, timing, motion, keys and the back label's room; products own layout and look. Markup opts in:

- **Announcements**: one visually hidden `role="status"` in the page, and one in each open modal so a sheet's news is heard. `design.announce(text)` clears it, then fills it on the next frame.
- **Focus**: opening any `dialog.dialog` focuses its first field for a keyboard or mouse, otherwise the dialog; closing returns focus to what opened it. `design.focusNear(element, fallback)` moves focus before a removal to the neighbor's first field, else its first control that isn't destructive, else the fallback. A prefilled text field is selected when it takes focus on open.
- **Sheets**: `a[data-sheet]` loads its `href` with `X-Fragment: 1` into one `#sheet`, prefetched on pointer down; after `--delay-loading` the tapped row's chevron becomes a spinner, and repeat taps wait. A `[data-sheet]` link inside a sheet stacks a level: it slides in, the sheet eases to the new height, and the bar's `[data-cancel]` becomes a back link titled after the level below. Escape and the back link step back one level and focus the row you came from. On phones, drag a sheet's bar down to dismiss it. `design.sheet(url or markup, opener)` returns a promise of the close. New content fires `design:content`.
- **Menus**: `.menu[popover]` gets arrow keys, Home, End and type-ahead; opened by keyboard it focuses the checked item or the first; choosing one closes it and returns focus; with no script, Escape or a tap outside closes it. `design.menu(menu, x, y)` opens one at the pointer, for context menus.
- **Copy**: `[data-copy="id"]` copies that element's `data-value`, value or text; `a[data-copy-link]` copies its URL. The button shows its check for `--duration-notice` and says "Copied …". A refused copy shows nothing. `[data-reveal="id"]` swaps a masked secret for its `data-value`, and masks it again when the page is hidden.
- **Toast**: `design.toast(message, {label, run})` replaces the one toast. Without an action it stays its reading time, paused while hovered or focused; with one it stays until used, F6 reaches the action and Escape dismisses it.
- **Filter**: `input[data-search="filter"]` filters `data-list` rows by their `data-search-*` values (all terms, word starts, email aware, folding `data-fold-from` to `data-fold-to`), marks the matches, shows `[data-empty]` when none match, updates `[data-count]` and says "3 of 12 people" or "No results for …". Escape clears. Rows ease into place.
- **Live search**: `input[data-search="live"]` (or `"embed"`) loads results into `[data-results]` with `X-Fragment: 1`, cancelling stale requests, keeping history and picked rows, and staggering new rows in. Both fire `filter:applied`.
- **Gate**: a form's primary submit (inside it or tied by `form=`) is disabled only while the form is invalid by its own constraints (a required field empty, a pattern or type unmet). A form with no constrained field is never gated, nor is `method="dialog"`. It re-checks on input and change, and when a sheet's content arrives (`design:content`).
- **Validation**: a field that fails on submit, on Enter or on leaving it after a change gets `aria-invalid="true"`; in a `.field` its `.field__error` (a `span`, created if absent) shows the browser's `validationMessage` and the browser's own bubble is suppressed; a field outside a `.field` keeps the bubble. Both clear as soon as the field is valid. Never on first load. An Enter another control handled marks nothing.
- **Busy**: a form's submitter gets `aria-busy="true"` and ignores repeats until the page changes; an `aria-disabled` submitter never submits.
- **Combobox**: `design.combobox(input, {search, choose, minimum})` waits 200ms, ignores stale answers, highlights the first match, marks matched letters, says "4 suggestions" once per change; Down opens, Up, Down, Home and End move, hover follows the pointer, Enter chooses, Escape closes.
- **Tabs**: `[role="tablist"]` > `[role="tab"][aria-controls]` gets a roving tab stop, arrows, Home and End, and shows its panel.
- **Shortcuts**: every control with `aria-keyshortcuts` ("/ Meta+K Control+K", "N", "1") is a shortcut: fields take focus, others are pressed. Ignored while typing, with Alt and under a modal; a control inside `main` wins over one outside it. ? lists them all in a sheet.
- **Page changes**: same-origin navigations cross-fade with a slide, backward ones the other way; a list row grows into the detail page it opens.

## Icons

`icons.svg` holds 38 glyphs as `<symbol>`s: grids of 12 (`chevron-right`, `chevron-left`, `caret-down`), 16 (`add`, `minus`, `more`, `link`, `check`, `eye`, `eye-off`, `trash`, `duplicate` (also copy), `external-link`, `fit`, `arrange`, `search`, `sidebar`) and 24 (`check-circle`, `info-circle`, `exclaim-circle`, `exclaim-triangle`, `envelope`, `tray`, `folder`, `diagram`, `search-empty`, `person`, `people`, `home`, `apps`, `partners`, `inbox`, `support`, `organization`, `roles`, `permissions`, `activity`, `limits`). `.icon` draws 16, `.icon--sm` 12, `.icon--lg` 24; the stroke stays 1.5px at any size (`.icon--bold` 2px beside a semibold label). Round caps and joins, no fills, color from the adjacent text. An icon-only button always has an aria-label. Exports that must stand alone inline the paths.

## Patterns

1. **Page frame**: sticky 56 nav bar, then `.page`. Padding 48, 16 on phones. Title 28/600, or a 34 large title that folds into the bar.
2. **Navigation**: a sidebar at 900 and up; below it a tab bar, a segmented control or the nav bar alone. Labels with or without a glyph. The nav bar is the same on every page of a product: logo left, title centre, then page actions, global links and account on the right. The account button shows only on top-level pages: a page with a back link, or a sheet, has none. Nothing else hides on its own page; the current item takes `aria-current="page"`. On phones, actions marked `.navbar__fold` move into a `.navbar__more` button (the `more` glyph) that opens a `.menu--navbar` popover. Signed out shows Sign In and the main action; signed in shows the account avatar.
3. **Forms**: stacked (`.form` > `.field`) or grouped (inset fields in list rows). One primary action: in a sheet it is the bar's primary pill, named for what it does (Send, Create, Done), disabled until the form is complete. Explanations sit in the footer of the group they explain; a form never opens with a loose line of text. A form with a field a person fills (any input but a hidden one, a select or a textarea) submits to its own action with a `.btn`, never a cell; a cell with `formaction` to another address, a flow's `.flow__options` choices and a form of hidden inputs only are row actions.
4. **Feedback**: notice for page state, toast for a finished action (it stays `--duration-notice` or as long as reading it takes at `--reading-words-per-minute`, whichever is longer, and waits while the pointer is over it), dialog for a decision, an outcome page (`.outcome`) for a result that ends a flow, including not found, and an alert (`dialog--alert` > `.outcome`, error glyph, one OK) for an action that failed. Say what happened, then what to do. A server error also shows `.outcome__code` "Reference" and 8 characters the server logged with the cause, so the user can quote it.
5. **Lists and data**: grouped lists for settings and details, plain lists for indexes, tables for dense reference.
6. **Empty**: a glyph, a title and one sentence. The create action stays in the bar; an empty state never repeats it.
7. **Loading**: a spinner in place of the content it waits for.
8. **Access**: skip link first, focus order follows reading order, 44 targets on touch, a linked heading lands clear of the bar (`html` takes `scroll-padding-top` of the bar and 16).
9. **Appearance**: light and dark follow the system; forced colors and reduced motion honored.
10. **Copy**: Title Case for buttons, titles and menu items; sentence case elsewhere; follow the brand voice guide, `voice.md` in this repo, the one source for all copy in every repo. Delivery copies it to each product; every other repo's rules point here; `go run ./checks voice <dir>` catches in HTML: dashes, exclamation marks, emoji, log in, pick, application, spelled-out numbers, uncontracted not, UK spellings (a capitalized name in body text is skipped, never one in a title, label, button, menu item or heading), a comma before and or or in a list, vague words, pipe separators, Title Case on buttons, menu items, tabs, labels and titles, punctuation on alert and status titles, an empty state of more than one sentence, and the "Last updated" date.
11. **Long-form**: docs, FAQ, privacy and security pages use the document template; rendered documents inside an app use `.prose`. A marketing page leads with a headline, a statement that ends with a period ("Questions, answered."); a reference page is titled by its name in Title Case ("Privacy Policy", "Go SDK"). Every document shows "Last updated <Month D, YYYY>" and its reading time (an FAQ shows its question count). Pages with more than 3 sections get contents. A docs series gets chips and previous/next. An FAQ is grouped by topic, filterable, every question linkable, and ends with Still Have Questions?
12. **One canvas**: every page in every product, public or signed in, sits on the plain background, with hairline-bordered cards and lists. Bars and the sidebar are the only tinted surfaces. A page may put `.site` on `body` so the footer sits at the bottom.
13. **Not found**: the same in every product: nav bar, `.outcome` with `.outcome__code` "Error 404", "Page Not Found", the product's one-line message, one button back to the product, footer. No glyph: outcome glyphs mean success, warning, error or progress.
14. **Footer**: `footer.footer.footer--rule` > `.wrap.footer__row` > the product's own lines, in its words, with the © line last. Links sit in `nav.footer__links` or inline; separators are spaced middle dots.
15. **Bar actions**: a page's actions sit in the bar's right slot, before the account button. The page's create or add action is its one primary pill; Edit, Share, Rename and Export are plain. Actions on a whole project or app live on that project's or app's own page, not on its children. On phones the plain actions fold into More.

## Designing

1. One job per view. Show, never explain: no tours, getting-started modals or tooltips.
2. Native first. A custom component names the interaction the native one cannot do.
3. Per view: at most 3 hierarchy levels, one secondary action and one destructive action. Related blocks sit tight, with a larger gap before the form or actions.
4. Color never carries meaning alone: shape, position or text says the same.
5. Empty and error states come first. An error is specific, never repeats the button's action, never promises a time.
6. A form POST redirects to a GET. Never land where the main action undoes what was done. A high-stakes change ends on its own outcome page with one Continue.
7. Dense beats sparse. A flow takes the fewest steps its decisions need, each decision justified, each exit point mitigated, top-aligned.
8. An element the view works without is cut; then every word that changes no meaning.
9. No friction against leaving, canceling or deleting.

## Sync

Every push to `main` runs `.github/workflows/sync.yml`:

1. **Checks**: `go run ./checks contrast`, `go run ./checks literals . tokens checks skill icons.svg` and `node scripts/layout.cjs .`, the layout tests, which drive Chrome over its DevTools protocol.
2. **Sync**, one job per product in `products.json` without `"delivery": "review"`: `scripts/deliver.sh` writes the files (tokens, `components.css`, `icons.svg`, `behaviors.js`, `document.js`, `voice.md`, `styles.css`, `profile.css`, and the check as Guard says) to the product's directory from `products.json` and writes `styles.css` as one file, the imports in order, so a browser never mixes files from two versions. The job applies `renames.json`, then runs the product's delivered `check.sh`, which fails on stray literals, bare hovers, copy slips, Title Case and date lines, product CSS that names a design class or sets more than layout on one, unknown parts and modifiers of design classes and orphan parts, component and page structure, profile choices, a second `.btn--primary` in one view, `.btn--sm` in a form, list row or cell, a type size below `--text-40` that changes with the viewport, display type that steps more than once, at a width other than 900 or to a bigger token below 900, theme colors that differ from `--color-background`, and on tokens or classes the new version drops. Theme colors may be hardcoded only where a product can't read the tokens, like a static site. When the checks pass, it commits one change to that repo citing this commit (`commit.txt`). Products don't wait on each other: one that fails keeps its current files until it's fixed, and the others still get theirs.
3. **Guard**: each product runs the guard once per push from its own `.github/workflows/design.yml`, except website, which runs the same checks from its `scripts/check`. Where a deploy workflow calls the guard, `products.json` gives the product `"guard": "call"`, and delivery writes `scripts/guard.yml` (a `workflow_call` only, with the product's design directory) as that file, so the deploy lists it in `needs` and the guard never also runs on its own push. A product without the key keeps its own file, which delivery never touches. The guard fails when a delivered file no longer matches `checksums.txt`, which delivery writes, when a file was added or removed, or when a product check fails. Delivery ships the whole check into the product's design directory, in the hidden folder `.check/` (which Go never embeds): `check.sh`, the Go sources in `checks/`, `.go-version`, `exclusions.txt` from `products.json`, `profile.txt`, `theme.sh` and `theme-colors.txt`, beside `readme.md` (Go's own `go.mod` would stop the product embedding the folder, so none is delivered). Every push runs each product check from that copy (proteus's only on a push that changes `server/` or `Owner.toml`): `sh <design directory>/.check/check.sh <product root>`, after `actions/setup-go` on its `.check/.go-version`. It runs the same script the sync runs, reads nothing from this repo and needs no token. From what it serves, each product excludes `.check/` and every delivered file its pages don't load.

The literal check skips `<meta name="theme-color">` lines, which cannot read tokens. The literal and copy checks skip every file or folder whose name starts with `mock-`, so name mockups that way.

Sync runs only when the repository variable `SYNC_ENABLED` is `true`, with `SYNC_CLIENT_ID` and the `SYNC_APP_PRIVATE_KEY` secret of a GitHub App installed on every synced product repo. An entry with `"delivery": "review"` gets no sync job: the session that pushes to main here delivers it the same way (`scripts/deliver.sh`, the renames, the product's own checks given the previous `components.css`) into a clone of the product, and pushes that to the product's main after a fresh review.

Renames: add `{"tokens": {"--old": "--new"}, "classes": {"old": "new"}}` entries to `renames.json` in the same commit that renames, or `"old": ""` to drop a class from markup; the sync rewrites every use, so no alias is ever needed. Before a class is dropped, each product that uses it moves to classes of its own names, so its change lands first.
